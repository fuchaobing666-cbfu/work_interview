# 库存助手交付说明

## 处理说明

### 职责划分

- **Agent（`agent.py`）**：理解请求中的 `market`、`sku`，加载并注入库存 Skill，编排模型与工具的多轮交互；库存查询工具参数强制使用请求市场和 SKU；检查工具结果归属，阻止市场或 SKU 不匹配的数据进入回答校验；对同步工具调用实施超时控制，并对超时按配置有限重试。
- **Skill（`skills/inventory/SKILL.md`，兼容路径 `skills/inventory-risk/SKILL.md`）**：规定库存指标的输入校验、覆盖天数计算、风险等级规则和回答格式。覆盖天数为 `ending_stock / shipped_units * 7`；零发货输出 `null` / `UNKNOWN`；低于阈值为 `P0`，否则为 `OBSERVE`。Skill 不调用 MCP、不访问文件或网络。
- **MCP（`mcp_server.py`、`mcp_client.py`）**：服务端读取库存数据源，并以 `market + sku` 精确匹配、拒绝缺失或重复记录；客户端负责 MCP stdio 会话及工具发现/调用，并以 `UFLOW_MCP_TIMEOUT_SECONDS` 限制单次操作等待时间。MCP 返回原始指标和阈值配置，不计算覆盖天数或风险等级。

### 改造点

- `mcp_server.py` 按市场和 SKU 双键隔离库存记录，不再只按 SKU 命中。
- `mcp_client.py` 为会话初始化、工具发现和工具调用增加环境可配置超时，默认 10 秒。
- `agent.py` 使用 Skill 上下文完成多轮编排；通过 `tool_call_id` 回传工具结果；设置 `tool_timeout_seconds`（默认 10 秒）和 `tool_timeout_retries`（默认重试 1 次）；市场/SKU 参数以用户请求为准。
- 市场数据通过 `UFLOW_INVENTORY_PATH` 指向的数据文件提供。接入新市场、已有通用阈值规则时，加入该市场的库存记录即可复用同一 Agent、Skill 和 MCP 实现，不需要新增市场专属代码或复制 Skill。

## 已知限制与业务确认项

1. 当前 MCP 的 `get_risk_rule()` 仍返回全局阈值 `p0_below_days: 3`。新增市场的**库存数据接入**已验证为只加数据即可，但如果不同市场需要不同阈值，还需将阈值配置迁移为按市场键查询的数据配置；本次没有验证或声称市场专属阈值配置已经落地。
2. 当前演示数据源是 JSON 文件；尚未验证数据库、远程库存 API、并发写入或大数据量场景。记录唯一性依赖 `(market, sku)` 组合键。
3. Agent 的超时包装使用守护线程，Python 无法强制终止已经开始的同步调用。助手可按时返回超时错误，但底层卡住的调用线程可能继续运行至其自身结束；生产环境应优先使用具有原生截止时间/取消能力的传输层。
4. `mcp_client.py` 每次工具请求都会建立独立 stdio 会话，超时默认值需要结合实际后端延迟与服务资源调整。Agent 工具超时与 MCP 客户端超时是两层限制，应协调配置。
5. 本地已通过模拟模型及工具测试；没有执行依赖外部考场模型凭据的真实模型演示。业务仍需确认不同市场是否使用相同的 3 天阈值，以及周发货口径、库存单位和多条时间区间数据的取数规则。
