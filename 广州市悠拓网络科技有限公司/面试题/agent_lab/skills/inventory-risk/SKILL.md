# 通用库存分析 Skill

## 职责与边界

只负责对调用方已经提供的库存数据和适用业务配置进行校验、计算、分级并说明理由。不得调用 MCP、访问文件或网络、启动服务、猜测数据，也不得把工具/API 调用步骤作为本 Skill 的执行逻辑。数据获取、按请求查找配置、工具重试和错误处理由外部 Agent/适配层负责。

本 Skill 不维护市场白名单，不在规则中枚举国家、地区或 SKU。市场是配置键和数据隔离维度，不改变通用计算公式。

## 输入约定

调用方应提供：

- 请求：`market`、`sku`。
- 已选中的唯一指标记录：`market`、`sku`、`shipped_units`、`ending_stock`。发货量为本周发货件数，库存为期末库存件数。
- 适用于该市场的风险配置：`p0_below_days`。配置应由调用方按 `market` 选择并传入，不由 Skill 查询。为兼容当前业务约定，只有在明确未提供市场覆盖值、且调用方确认可使用全局默认规则时，才可使用全局默认阈值 3 天；新接入市场应在配置中显式提供阈值。

多市场配置采用数据驱动方式：每个市场在配置中有独立键值项，至少声明 `p0_below_days`；可按业务需要增加其他经批准的规则参数。新增市场只需增加市场配置和对应数据，不应增加市场专属代码、分支或复制本 Skill。配置选择必须精确匹配请求的 `market`，不允许回退到另一个市场的配置。

## 校验与计算

1. 确认请求、指标记录和配置完整；指标记录的 `market` 与 `sku` 必须同时精确等于请求值。不得仅按 SKU 匹配，不得跨市场借用数据。缺少记录、匹配多条或配置不明确时，不输出推测性结论。
2. `shipped_units`、`ending_stock`、`p0_below_days` 必须为有限且非负数；发货量和库存应使用相同计量单位。无效、负数、非数值或非有限数值均视为输入无效。
3. 若 `shipped_units == 0`，设 `cover_days = null`、`risk = "UNKNOWN"`，说明本周无发货，无法据此计算库存覆盖天数；不要除以零或据此判定 P0/OBSERVE。
4. 否则按 `cover_days = ending_stock / shipped_units * 7` 计算，单位为天。
5. 若 `cover_days < p0_below_days`，风险为 `P0`；否则（含恰好等于阈值）为 `OBSERVE`。比较必须使用所选市场的有效阈值，不得按市场名称自行改变规则。
6. 理由应简洁说明库存、周发货、覆盖天数及所用阈值；零发货时说明 `UNKNOWN` 的原因。不要将计算值伪装成未经舍入的精度；输出数值可合理舍入，但不得改变分级判断所用的原始计算值。

## 输出约定

成功时返回 JSON 对象，至少包含：

- `market`：原样返回请求市场。
- `sku`：原样返回请求 SKU。
- `cover_days`：覆盖天数数值；零发货时为 `null`。
- `risk`：`P0`、`OBSERVE` 或 `UNKNOWN`。
- `reason`：可追溯到输入数据和配置的简要说明。

输入缺失、冲突或无效时，不编造成功答案；将具体问题交由调用方按其结构化错误协议处理。不得把工具失败或缺少证据转换成库存风险结论。
